## 2026-04-27 - Path Traversal Vulnerability in File System Tools
**Vulnerability:** The `FileTool` operations (`read`, `write`, `patch`) allowed arbitrary file system access because user-provided paths were used directly without sanitization, exposing a path traversal risk.
**Learning:** File path inputs to SDK operations must be properly resolved and validated to prevent unauthorized access outside the intended working directory. Unrestricted access breaks the security boundaries of an agentic execution environment.
**Prevention:** Always use `path.resolve(process.cwd(), unsafePath)` and verify that the resulting absolute path begins with `process.cwd()`. Implement secure failure paths and never expose raw internal file structures on error.
## 2026-05-15 - Unbounded Resource Execution Vulnerability in External Connectors and Shell Tools
**Vulnerability:** The `ShellTool` and `AgentConnector` lacked execution and network timeouts (`execAsync` ran indefinitely, and Axios had no timeout or size limit). An attacker or malfunctioning LLM could provide a long-running shell command or cause a massive payload response, leading to Denial of Service (DoS) through resource exhaustion.
**Learning:** SDK tools acting as intermediaries between external systems (LLMs, OS shell) must enforce strict boundary limits on compute and memory. Trusting external inputs to resolve in a timely manner without enforced boundaries is a severe reliability and security risk.
**Prevention:** Always define explicit timeouts (e.g., 30,000ms) and buffer limits (`maxBuffer`, `maxContentLength`, `maxBodyLength`) on shell executions (`child_process.exec`) and HTTP clients (`axios`).
